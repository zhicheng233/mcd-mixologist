## 一、本 skill 会用到的 10 个 Tool

### 只读（安全，随便调）

| Tool | 关键参数 | 返回什么 | 本 skill 用在哪 |
|---|---|---|---|
| `now-time-info` | 无 | 当前完整时间 | 判断餐段 |
| `campaign-calendar` | 月份 | 当月活动（进行中/往期/未来） | 找"今日限定" |
| `query-nearby-stores` | 地址/经纬度 | 附近门店列表 | 让用户选店 |
| `query-meals` | `storeCode` | 在售餐品、分类、餐品编码 | 确定"今天有什么" |
| `query-meal-detail` | 餐品编码 | 套餐组成、可替换项 | 用户要换单品时 |
| `query-store-coupons` | 门店 | 该店可用券 | "装饰"位素材 |
| `available-coupons` | 无 | 麦麦省可领券 | 用户问"有什么券" |
| `calculate-price` | 门店 + 商品列表 + 券 | 商品金额、配送费、优惠、应付 | **核价，展示前必调** |
| `list-nutrition-foods` | 无 | 餐品营养表 | 复核热量 |
| `query-my-account` | 无 | 积分账户 | 可选，用于彩蛋 |

### 写操作（必须用户明确同意）

| Tool | 后果 | 调用前提 |
|---|---|---|
| `auto-bind-coupons` | 券真实入账卡包 | 用户说"帮我领" |
| `create-order` | 真实下单，返回支付链接 | 用户说"下单"，且已复述全部明细 |
| `draw-lottery` | 消耗真实积分 | 本 skill 不使用 |

## 二、调用纪律（六条）

### 1. 先时间，后一切

`now-time-info` 永远第一个调。不知道几点就推荐餐，是这类 skill 最常见的翻车点。

### 2. 门店是菜单的前提

`query-meals` 必须带 `storeCode`。没有门店就先 `query-nearby-stores`，
不要用"默认门店"或"全国菜单"糊弄。

### 3. 展示的价格只能来自 `calculate-price`

本地 `data/flavor-db.json` 里的 `price` 是**离线演示快照**。
任何对外展示的价格，要么来自 `calculate-price`，要么明确标注"演示价"。

### 4. 空数据不是错误

麦当劳 MCP 在无数据时可能返回中文文案（如「暂无可用优惠券」），
而不是空数组。解析时一律按"空集"处理，不要当成调用失败，也不要重试。

### 5. 返回体可能不是 JSON

真实数据可能藏在 `## Original Response` 段之后。解析顺序：

```
原始文本
  → 若含 "## Original Response"，取其后部分
  → 尝试 json.loads
  → 失败则视为纯文本，按行/逗号解析（如营养表）
  → 仍失败则按空集处理，并在卡片上注明"该项数据暂不可用"
```

### 6. 限流 600 次/分钟

配方搜索是本地计算，不消耗额度。真正要控制的是：
不要为了"多试几种"而反复调 `query-meals` / `calculate-price`。
一次会话里，`query-meals` 调一次就够，`calculate-price` 每杯调一次。

## 三、典型失败与应对

| 现象 | 可能原因 | 怎么办 |
|---|---|---|
| 401 | Token 无效或过期 | 让用户重新申请，不要重试 |
| 429 | 超过 600 次/分钟 | 停止调用，等 1 分钟，说明原因 |
| 门店列表为空 | 地址太偏或超出配送范围 | 让用户换个地址或改到店 |
| `query-meals` 返回空 | 门店打烊或非营业时段 | 如实说明，建议换店或改天 |
| 券查到了但核价没减 | 券不适用该商品/该店 | 不挂这张券，如实说明 |
| 营养数据解析失败 | 返回的是纯文本表格 | 按行切、逗号 split；实在不行标"暂无" |

---

## 四、绝对不要做的事

- ❌ 编造门店、餐品、价格、券、活动
- ❌ 把"示例数据"当成"当前数据"
- ❌ 用本地历史价冒充实时价
- ❌ 未经用户明确同意调用任何写操作
- ❌ 因为接口失败就自己"猜一个"结果
- ❌ 在分享卡片或日志里写入用户地址、手机号、订单号
