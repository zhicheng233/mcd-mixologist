# 心情风味轮

本文件是 `data/mood-db.json` 的可读版本。给两种人看：想改配方的贡献者，和想理解
"为什么推荐这个"的用户。

---

## 一、六个风味维度

一杯麦当劳的风味画像，用 6 个 0~1 的数描述：

| 维度 | 中文 | 含义 | 高分的典型餐品 |
|---|---|---|---|
| `sweet` | 甜 | 甜度 | 芬达、麦旋风、热巧克力 |
| `heat` | 辣 | 辣度 | 麦辣鸡腿堡、麦辣鸡翅 |
| `umami` | 咸鲜 | 肉感与咸鲜厚度 | 安格斯厚牛堡、双层吉士 |
| `fresh` | 清爽 | 解腻、气泡、酸度 | 蔬菜沙拉、零度可乐、橙汁 |
| `rich` | 浓郁 | 油脂感与厚重 | 双层吉士、大薯条 |
| `warm` | 温热 | 热食为 1，冰饮为 0 | 热巧克力、豆浆 vs 可乐、圆筒 |

> 为什么是这 6 个而不是 3 个？
> 试过只留「甜/辣/浓」，结果 8 种心情会推出同一杯——因为"疲惫"和"犒赏"在
> 这三轴上几乎重合。加进「清爽」和「温热」之后才分得开：疲惫要热的，亢奋要冰的。

## 二、八种心情

| 心情 | 触发场景 | 风味目标（甜/辣/咸鲜/清爽/浓郁/温热） | 回避 | 一杯的代表 |
|---|---|---|---|---|
| **疲惫** | 加班、通勤、被掏空 | 0.35 / 0.15 / 0.70 / 0.30 / 0.80 / 0.90 | 咖啡因 | 热的、厚的、不用动脑的 |
| **烦躁** | 开会、被气到、心态崩 | 0.15 / 0.85 / 0.70 / 0.45 / 0.70 / 0.60 | 糖 | 辣度顶上来，气就顺了 |
| **空虚** | 饿、麻木、不知道吃什么 | 0.40 / 0.30 / 0.85 / 0.15 / 0.95 / 0.75 | — | 浓到能盖住那个洞 |
| **亢奋** | 上线成功、发布、搞定了 | 0.50 / 0.25 / 0.55 / 0.80 / 0.40 / 0.45 | — | 清亮、有气泡 |
| **孤独** | 一个人、深夜、想家 | 0.60 / 0.10 / 0.55 / 0.35 / 0.70 / 0.95 | — | 温度比味道重要 |
| **犒赏** | 发工资、生日、值得 | 0.85 / 0.10 / 0.65 / 0.30 / 0.85 / 0.60 | — | 今天不算热量 |
| **平静** | 普通的一天 | 0.40 / 0.15 / 0.55 / 0.85 / 0.40 / 0.50 | — | 吃完不后悔 |
| **焦虑** | deadline、赶进度、睡不着 | 0.30 / 0.05 / 0.60 / 0.50 / 0.55 / 0.90 | 咖啡因、油炸 | 别让胃替情绪加班 |

### 设计原则

1. **每种心情必须和至少两种其他心情显著不同**，否则就是八张一样的脸。
   自测里有一条专门检查"疲惫"和"亢奋"的首杯不能是同一个基酒。
2. **"回避"不是禁忌**。它是扣分项，不是硬过滤——用户非要点也不是不行，
   但话术里要说清楚为什么这杯不合适。
3. **温度是最强的区分维度**。八种心情里，`warm` 从 0.35 到 0.95 拉满，
   因为人对"想吃热的"这件事的感知远比"想吃咸的"强烈。
4. **目标向量必须是这份菜单能兑现的**。这是调过一轮才发现的坑：
   "亢奋"最初写的是 `heat 0.60 + fresh 0.80`（"清爽为主，微辣提神"），
   结果最优解只有 54%——因为在麦当劳的菜单里，辣就等于油炸、等于浓郁，
   和清爽天然互斥。把 `heat` 降到 0.25、`warm` 提到 0.45 之后，
   最优解变成"吉士汉堡 + 蔬菜沙拉 + 橙汁"，适配度 69%，配方也终于说得通。
   **一个永远够不着的目标向量，只会让所有餐品一起不及格。**

## 三、心情是怎么被认出来的

`mix.py` 用关键词匹配，不做语义模型。原因：确定性、可测、不依赖网络。

每种心情有一组 `aliases`，匹配时**取最长命中**，所以：

- "累" → 疲惫
- "累到没力气" → 疲惫（更长，但仍然对）
- "加班到十点" → 疲惫

如果一句话里同时命中两种心情（"开心但很累"），取更长的那个别名；
长度相同则取配置文件里靠前的。这种时候 agent 应该反问一句，而不是硬猜。

## 四、用户嘴上说的偏好，优先级高于心情

`CRAVE_MAP` 会把显式偏好叠加到心情目标上：

| 用户说 | 叠加 |
|---|---|
| 甜 | `sweet +0.35` |
| 辣 | `heat +0.35` |
| 清爽 | `fresh +0.35`、`rich −0.15` |
| 清淡 | `fresh +0.30`、`rich −0.25`、`heat −0.20` |
| 浓 | `rich +0.30` |
| 热 | `warm +0.30` |
| 冰 | `warm −0.35` |
| 饱 | `rich +0.25`、`umami +0.15` |

叠加后裁剪回 `[0, 1]`。所以"很累但想喝点甜的"会得到一杯**热的 + 甜的**，
而不是单纯按疲惫走。

## 五、怎么加一种新心情

1. 在 `data/mood-db.json` 的 `moods` 里加一条，6 个维度都要给
2. 给它至少 3 个 `aliases`、3 个 `names`（配方名）、3 条 `notes`（调酒师笔记）
3. 跑 `python scripts/mix.py --selftest`
4. **手动对比**：和现有 8 种心情的首杯比一遍，如果撞了，说明向量没做出差异
5. 在本文的表格里补一行

> 新增心情最容易犯的错：把 6 个维度都往 0.7 靠。这样它会同时像所有人，
> 结果谁也认不出它。差异化来自"至少一维接近 0、至少一维接近 1"。
